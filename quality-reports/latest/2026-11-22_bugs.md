## Confirmed Bugs

### [BUG-001] Incorrect State Assignment in UpdaterSettingsView

**Classification:** CONFIRMED BUG
**Severity:** High
**Confidence:** High
**Category:** Correctness
**Skill:** bug-finder-swift
**Location:** src/WOA/WOA.swift:148

**Evidence:**
In UpdaterSettingsView.body, the onChange handler for automaticallyDownloadsUpdates toggle assigns the wrong variable:
`swift
Toggle("Automatically download updates", isOn: \)
    .disabled(!automaticallyChecksForUpdates)
    .onChange(of: automaticallyDownloadsUpdates) { 
        updater.automaticallyDownloadsUpdates = automaticallyChecksForUpdates  // WRONG VARIABLE
    }
`

**Trigger:** User toggles the "Automatically download updates" toggle.

**Observed/Expected:**
- Observed: When toggled, updater.automaticallyDownloadsUpdates gets the value of automaticallyChecksForUpdates instead
- Expected: updater.automaticallyDownloadsUpdates should be set to automaticallyDownloadsUpdates

**Impact:** 
- The toggle does not work as intended
- Toggling automatic downloads changes the automatic checks setting instead
- Users cannot independently control these two settings
- Breaks core Sparkle auto-update feature control

**Root Cause:** Copy-paste error or variable name typo in closure

**Recommendation:** Change line 148 to: updater.automaticallyDownloadsUpdates = automaticallyDownloadsUpdates

**Validation:** Unit test - toggle both switches independently and verify each updates its corresponding updater property

### [BUG-002] Debug Print Statements in Production Code

**Classification:** CONFIRMED BUG
**Severity:** Medium
**Confidence:** High
**Category:** Error handling / Logging
**Skill:** bug-finder-swift
**Location:** src/WOA/WOA.swift:68-70

**Evidence:**
In SparkleUpdaterDelegate.updater() error handler, three print() statements appear:
`swift
print(Bundle.main.object(forInfoDictionaryKey: "CFBundleVersion")!)
print(Bundle.main.object(forInfoDictionaryKey: "CFBundleShortVersionString")!)
print(Bundle.main.infoDictionary?["CFBundleShortVersionString"] ?? "")
`

**Trigger:** Sparkle update cycle completes with an error

**Observed/Expected:**
- Observed: Version information printed to stdout/console
- Expected: All logging should use AppLogger (OSLog), not print()

**Impact:**
- Violates project logging standards (custom instructions specify OSLog/AppLogger only)
- Version information exposed without privacy modifier
- Inconsistent with rest of error handling which uses AppLogger
- Debug code accidentally left in production path

**Root Cause:** Debug statements left in after development/testing

**Recommendation:** Remove all three print() statements and use AppLogger if version logging is needed

**Validation:** Code search - confirm no print() statements remain in src/

## Probable Bugs

### [BUG-004] Force Unwrap in Keychain Error Handling

**Classification:** PROBABLE BUG
**Severity:** Medium
**Confidence:** Medium
**Category:** Correctness / Error Handling
**Skill:** bug-finder-swift
**Location:** src/WOA/WOA.swift:68

**Evidence:**
Force unwrap on Bundle.main.object() result without null check:
`swift
print(Bundle.main.object(forInfoDictionaryKey: "CFBundleVersion")!)
`

Compare to line 70 which uses safe optional chaining:
`swift
Bundle.main.infoDictionary?["CFBundleShortVersionString"] ?? ""
`

**Trigger:** If CFBundleVersion key is missing from Info.plist

**Observed/Expected:**
- Observed: Force unwrap with no nil check
- Expected: Optional chaining with fallback

**Impact:** 
- Crash in error handler if key is missing
- Occurs when user is least tolerant (updater already failed)

**Root Cause:** Inconsistent null-safety practices in same function

**Recommendation:** Use optional chaining with fallback like line 70

**Validation:** Test - remove CFBundleVersion from Info.plist and trigger update error, verify no crash

## Conditional Risks Requiring Validation

### [RISK-001] Broad Network Entitlements Not Fully Scoped

**Classification:** CONDITIONAL RISK
**Severity:** Medium
**Confidence:** Medium
**Category:** Security
**Skill:** bug-finder-swift
**Location:** src/WOA/Resources/WOA.entitlements

**Evidence:**
Entitlements include both network.client (broad outbound) and network.server (OAuth loopback):
`xml
<key>com.apple.security.network.client</key>
<true/>
<key>com.apple.security.network.server</key>
<true/>
`

**Concern:**
- network.server is justified for loopback OAuth listener
- network.client is unrestricted outbound access
- If vulnerability exists in network-handling code or dependencies, broad permission could be exploited

**Impact:** Medium risk in context of otherwise sound sandboxing

**Recommendation (not blocking, but best practice):**
- Document which features require network.client
- Code audit to trace all network-making code
- Verify all use cases are intentional and from trusted sources
